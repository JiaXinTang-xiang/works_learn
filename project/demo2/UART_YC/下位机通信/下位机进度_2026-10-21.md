> 三个实际工程（H题1、telemetry-framework、CORE_TI）都接好了。协议与上位机

> SOF 分方向（0xA5 下 / 0xA6 上）两端一致。

## ✅ 已完成

### 1. 协议层（纯逻辑，三平台共用同一份）
- [uart_protocol.h](f103_biao/uart_protocol.h) / [uart_protocol.c](f103_biao/uart_protocol.c)：
  - CRC16/Modbus（0xA001 / 初值 0xFFFF，**位运算**实现，与上位机查表同结果）
  - 6 态流式解包状态机（SOF→LEN→CMD→PAYLOAD→CRC_LO→CRC_HI→EOF），抗分包/粘包/噪声
  - 帧打包 `Proto_BuildUplink`、命令分发 `Proto_Dispatch` → 全局 `vision_data`
  - `#pragma pack(push,1)` + `memcpy` 还原，防 Cortex-M 非对齐 HardFault
  - **无任何硬件寄存器 / HAL / DriverLib 依赖**，F103 / F407 / TI 直接复用同一份源码

### 2. 硬件层模板
- [f103_biao](f103_biao/README.md)（STM32F103 标准外设库）：
  `host_uart.h/.c` — USART1 初始化、RX 中断逐字节喂协议层、`Host_UART_Poll` 分发、发送接口
- [f407_hal](f407_hal/README.md)（STM32F407 HAL 库）：
  `host_uart.h/.c` — `HAL_UARTEx_ReceiveToIdle_DMA` 接收、弱回调 `HAL_UARTEx_RxEventCallback`、发送接口
- [ti](ti/README.md)（TI MSPM0 DriverLib）：
  `host_uart.h/.c` — 对应 SysConfig 的 Communication 串口（UART1），RX 中断喂协议层、发送接口

## ❌ 还没写 / 待办

### A. 功能缺失（代码里完全没实现）
1. **心跳 `0x00`**：命令字预留了，但没实现收发逻辑。后续做「上位机卡死 → 下位机急停」看门狗。
2. **任务命令 `0x01` 无序列号 / 重传**：一次性下发，中途丢帧无补偿。若任务触发是「发一次必须收到」的关键命令，需要加 seq + 超时重发。
3. **QR「和 == 12」校验**：只在 `QrPayload_t` 注释里写了规则，`Proto_Dispatch` 只查了 `len == 6`，**没校验 6 位数字之和是否为 12**。
4. **解包错误静默丢弃**：LEN 非法 / CRC 失败时直接 `s_state = 0` 重找帧头，**没有错误计数**，无法判断是噪声、线松还是两端协议不一致。

### B. 写了接口、没接业务
5. **里程计 / 陀螺仪发送**：`Host_UART_SendOdom` / `Host_UART_SendGyro` 已写好，但 OPS 未装，还没接到实际数据源，先用测试变量占位。

### C. 收尾 / 清理
6. **H题1 死文件**：`System/UART.c`、`System/UART.h`、`System/UART.h.bak`（旧串口）已不再被引用，可删。
7. **H题1 编码**：新加文件是 UTF-8，工程旧文件是 GBK，Keil 里中文注释可能乱码（不影响编译）。
8. **`last_cmd` 类型**：`uart_protocol.h` 里写成 `uint16_t`，命令字是单字节，应为 `uint8_t`（纯美观，不影响功能）。
9. **CORE_TI 还没在 Keil 里编译验证**：本机没有 TI 工具链，`host_uart.c` 的 API 名已对照
   `dl_uart.h`/`dl_uart_main.h` 逐一核对，但需在 Keil 里 Rebuild 跑通 + 回环联调。
   （另：SysConfig 的 115200 实际是 115190.78，误差 0.008%，UART 可容忍，互通没问题。）
