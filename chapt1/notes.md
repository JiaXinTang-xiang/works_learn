# 第一章笔记：C 语言速通（变量 → 指针 → 结构体）

> 用法：这是「速查 + 坑清单」，不是教材复述。复习时先看每节的一句话本质，再看坑清单。
> 建议：把你自己栽过的坑补进去，那才是笔记真正值钱的部分。

---

## 1. 数据类型

**一句话**：变量 = 命名的内存空间；类型决定「多大、存什么范围」。

- `int` 4 字节 ±21 亿，`short` 2 字节，`long long` 8 字节（大数加 `LL` 后缀）。
- **机器人/通信里只用精确宽度**：`uint8_t`(0~255)、`uint16_t`、`int16_t`… 来自 `<stdint.h>`。
- `float` 4 字节（精度 6~7 位，机器人坐标够用、串口省带宽）；`double` 8 字节。
- `char` = 1 字节整数（ASCII）；字符串 `"Hello"` 末尾自动带 `'\0'`。

## 2. printf 调试

**一句话**：学会调试器之前，printf 是第一条命。

- 速查：`%d` 整数 / `%f`·`%.2f` float / `%lf` double / `%c` 字符 / `%s` 字符串 / `%02X` 两位补零十六进制 / `%p` 地址 / `%zu` sizeof。
- ⚠️ **每条 printf 末尾带 `\n`**，否则可能攒在缓冲区里不显示，看起来像「没输出」。

## 3. 控制流

**一句话**：`if` 做判断，`for`/`while` 做重复。

- `==` 相等、`!=` 不等、`&&` 与、`||` 或、`!` 非。
- ⚠️ **头号新手 Bug**：`if (color = 1)` 是赋值不是比较，永远为真、还不报错。
- `for` 已知次数；`while` 未知次数（机器人主循环）。
- `break` 跳出循环；`continue` 跳过本次进入下一轮。

## 4. 函数

**一句话**：把代码拆成可复用零件，声明放头文件、实现放 .c。

- **值传递**：参数永远是「副本」，函数里改不影响外面。
- 想真正改外部变量 → 传地址（指针），见 6.3。

## 5. 数组

**一句话**：一排连续格子，下标从 0 开始。

- ⚠️ **越界不报错**：`scores[5]`/`scores[-1]` 读脏数据、写坏别人内存 → 段错误温床。
- 二维数组 = 图像直觉来源：灰度图就是 行×列 的 `uint8_t` 矩阵（0~255），彩色图是 行×列×3(BGR)。

## 6. 指针 ⭐（本章灵魂）

**一句话**：指针 = 门牌号。`&` 问门牌号，`*` 顺着门牌号找人，`type*` 声明一个存门牌号的变量。

| 运算 | 含义 |
|---|---|
| `&a` | 取地址 |
| `*p` | 解引用（顺门牌号取值） |
| `int *p` | 声明指针 |
| `p + 1` | 地址按类型步长跳（char +1、int +4、double +8） |

- 64 位系统所有指针本身一律 8 字节。
- **指针类型决定两件事**：解引用读几个字节、`p+1` 跳多远。
- 数组名自动退化成首元素指针：`arr[2]` ≡ `*(p+2)`。
- 实战：串口收到裸字节，用 `uint8_t*` 逐字节解析协议。

## 7. 堆 vs 栈

| | 栈 | 堆 |
|---|---|---|
| 管理 | 编译器自动 | 手动 `malloc`/`free` |
| 大小 | 小(1~8MB) | 巨大(GB) |
| 生命周期 | 函数结束即销毁 | 直到 `free` |

- ⚠️ **悬垂指针**：返回局部变量的地址 = 送命。出了函数栈就死了，要么传缓冲区进去，要么 `malloc`。
- ⚠️ **内存泄漏**：主循环每帧 `malloc` 忘 `free`，60FPS 每秒漏 120MB → OOM 暴毙。铁律：**谁 malloc 谁 free**，`free` 后 `ptr = NULL`。

## 8. 结构体

**一句话**：把相关数据打包成一个类型。

- `typedef struct {...} Target;` 后可直接写 `Target`（不用带 `struct`）。
- `.` 用于变量取成员，`->` 用于指针取成员（`ptr->x` ≡ `(*ptr).x`）。
- ⚠️ **字节对齐巨坑**：`header(1B) + x(4B) + y(4B)` 默认 `sizeof` 是 **12** 不是 9，编译器塞了 3 字节 padding。跨设备通信结构体必须 `#pragma pack(push, 1)`。
- ⚠️ **单片机非对齐访问**会 HardFault 死机 → 打包/解包永远用 `memcpy`，别把裸字节缓冲区强转成结构体指针。

## 9. 头文件与多文件

- `.h`：声明 + 结构体 + 宏 + include；`.c`：实现。
- `#include "x.h"` = 把 x.h 内容复制粘贴进来。
- `#ifndef X_H ... #endif` 防重复包含。
- 编译：`gcc main.c target.c -o app`（用了 `math.h` 的 `sqrtf` 等要加 `-lm`）。

## 语法速查片段（1~3 行，扫一眼能想起来）

**精确宽度整型**
```c
uint8_t  b = 255;      // 1 字节无符号
uint16_t h = 65535;    // 2 字节
int16_t  s = -1000;    // 2 字节有符号
```

**printf 常用格式**
```c
printf("距离: %.2f 米, 十六进制: 0x%02X, 地址: %p\n", dist, 0x0A, (void*)p);
//      %d 整数  %f float  %lf double  %c 字符  %s 字符串  %zu sizeof
```

**指针三件套**
```c
int *p = &a;   // & 取地址（问门牌号）
*p = 100;      // * 解引用（顺门牌号找人）
p + 1;         // 按类型步长跳（int 跳 4、double 跳 8）
```

**指针遍历数组**
```c
for (int *p = arr; p < arr + 5; p++) printf("%d ", *p);
```

**函数内改外部变量（传地址）**
```c
void f(float *out) { *out = 1.5f; }   // 定义
f(&x);                                 // 调用：取地址传入
```

**堆内存 malloc / free**
```c
uint8_t *buf = (uint8_t*)malloc(W * H);   // 借
free(buf); buf = NULL;                     // 还 + 置空
```

**通信结构体紧凑对齐**
```c
#pragma pack(push, 1)   // 禁止 padding
typedef struct { uint8_t header; float x, y; } Packet;
#pragma pack(pop)
```

**memcpy 打包 / 解包（防非对齐访问）**
```c
memcpy(tx, &pkt, sizeof(pkt));   // 发送端
memcpy(&pkt, rx, sizeof(pkt));   // 接收端
```

**头文件保护宏**
```c
#ifndef X_H
#define X_H
/* 声明 / 结构体 */
#endif
```

**编译**
```bash
gcc main.c target.c -o app -lm
```

## 避坑清单（本章经典坑，踩到就打勾，可继续补自己的）

**语法坑**

- [ ] `if (color = 1)` 写成赋值 → 永远为真还不报错。判等必须 `==`。
- [ ] `printf` 末尾忘写 `\n` → 输出「消失」在缓冲区里。调试打印必带 `\n`，或加 `fflush(stdout)`。
- [ ] `printf` 格式符和参数类型不匹配（`%d` 配 float、`%s` 配 char）→ 输出乱码或崩溃。
- [ ] 数组下标越界 `arr[5]` / `arr[-1]` → 不报错，读到脏数据或写坏别人内存。
- [ ] `float` 字面量忘加 `f` 后缀（`1.5` 是 double，赋给 float 有精度警告）。
- [ ] 大整数忘加 `LL` 后缀 → 编译器当成 int/浮点，溢出或警告。

**指针 / 内存坑**

- [ ] 返回局部变量的指针（栈上数组出了函数就死）→ 乱码或 Segfault。改用调用者传缓冲区或 `malloc`。
- [ ] `malloc` 之后忘 `free` → 内存泄漏，主循环里会 OOM 暴毙。谁 `malloc` 谁 `free`，`free` 后置 `NULL`。
- [ ] 忘写 `*p` 和 `&a` 的方向：`&` 取地址、`*` 解引用，搞反必崩。
- [ ] `p + 1` 以为是「地址 +1」→ 其实是按类型步长跳（int 跳 4、double 跳 8）。
- [ ] 使用未初始化的野指针 → 段错误。指针要么给地址、要么给 `NULL`。

**结构体 / 通信坑**

- [ ] 跨设备通信结构体忘了 `#pragma pack(push, 1)` → `sizeof` 多出 padding，串口字节对不上。
- [ ] 把裸字节缓冲区强转成结构体指针直接读 → 单片机非对齐访问 HardFault，x86 上也违反严格别名规则。**只用 `memcpy` 打包解包**。
- [ ] 忽略大小端：小端内存字节是反的（`3F9DF3B6` → `B6 F3 9D 3F`），对接大端序设备要先翻转。

**编译 / 多文件坑**

- [ ] 用了 `math.h` 的 `sqrtf`/`sin` 等但编译没加 `-lm` → 链接报 undefined reference。
- [ ] 头文件忘写 `#ifndef ... #endif` 保护 → 重复包含导致重复定义。
- [ ] 编译只写了 `main.c` 忘写其它 `.c` → 链接报找不到函数。所有 `.c` 一起交给 gcc。

## 思考与反思

1. **指针的「门牌号」模型是本章唯一的心法**。内存就是一排带门牌号的格子，`&` 问门牌号、`*` 顺着门牌号找人。把这个画面焊在脑子里，后面 `p+1` 跳步长、数组退化成指针、函数传地址全都顺理成章——不用死记。
2. **C 不帮你兜底，纪律比语法重要**。越界、忘 `free`、返回栈上指针，C 统统不报错，出了错只能靠你自己排查。所以真正的门槛不是会写，是养成习惯：谁 `malloc` 谁 `free`、通信结构体必 `pack`、解包必 `memcpy`。
3. **「通信」的本质就是「字节流」**。一个 float 在串口上不过是 4 个裸字节，大小端决定它们的顺序，结构体 padding 会凭空多字节。搞通信时字节数必须精确到个位，否则另一端收到乱码。
4. **学了 C 才看得懂 Python 帮你做了什么**。Python 的 `struct` 打包、`ctypes` 对齐，本质都是本章这些底层原理的高层封装（见下面附录）。

## 附录：Python 里的等价写法（struct / ctypes）

Python 没有 `#pragma pack`，但有两个工具各对应一种场景（作业内容在 Python 里一行就能复现）：

**场景 A：打包/解包字节流（对应串口通信）→ `struct` 模块**

```python
import struct
struct.calcsize("<BdB")          # 10  ← 紧凑，等价 pragma pack(1)
struct.pack("<f", 1.234).hex()   # 'b6f39d3f' ← 正是作业2那 4 个字节
```

- 格式串 `<BdB` = 小端 + `uint8` + `double` + `uint8`，和 C 里的 `SensorDataPacked` 一回事。
- `<`（或 `=`）前缀 = 定死端序 + 不加对齐填充。`struct.pack` 打包、`struct.unpack` 解包，比 C 手写 `memcpy` 安全，没有非对齐 HardFault。

**场景 B：定义 C 风格结构体（内存布局对齐 C）→ `ctypes.Structure`**

```python
import ctypes
class Sensor(ctypes.Structure):
    _pack_ = 1              # ← 就是 pragma pack(push, 1)
    _fields_ = [("sensor_id", ctypes.c_uint8),
                ("temperature", ctypes.c_double),
                ("status", ctypes.c_uint8)]
ctypes.sizeof(Sensor)       # 10
```

- ⚠️ 实测坑：`struct.calcsize("@BdB")`（默认模式）是 **17** 不是 24，因为 Python 只在成员间填 padding、不在末尾补对齐，和 C 的 `sizeof` 不一致。**结论：跨设备通信永远用 `<` 或 `=` 前缀，别用默认 `@`。**
